# 普通目录统计实施与验收

## 月度双文件与历史归档（隔离库）

- 每个 Obsidian 安装的本地存储持久化独立编号。常规及退出保存交替写入 `月度/<安装编号>/<本机年月>-0.json` 和 `-1.json`。同一安装重启时从已验证的月文件恢复版本，下一次保存复用固定路径。一个月的文件保留该安装的各个运行编号及其最新累计快照。跨月时，同一次运行仍按原编号的最新版本计算一次。
- 读取月度文件时检查版本和历史来源完整性。已确认的版本记录在设备本地。同步回退时保留当前会话的有效统计，冷启动时提示等待同步或恢复，避免把缺失数据当作零。退出保存写入与在途异步写入不同的槽位。
- 命令「生成旧版统计归档」将 `记录/` 中尚未归档的有效记录写入 `归档/<内容摘要>.json`。原记录编号、版本、数据和操作关系保留。归档与散文件可并存，读取时按原编号去重。首次迁移基线及新产生的重命名、导入和清空操作沿用独立记录。归档命令只生成和校验归档。
- 该格式先用于隔离库。正式切换前需要所有参与同步的设备升级并完成真实 Fast Note Sync 双端验收。随后核对每份最新版和归档的内容摘要，在同步目录外留存备份，再由单台设备按复核清单清理散文件。
- 已在两套桌面 Obsidian 与回环 Fast Note Sync 服务验收。双端先离线保存，重连汇总为七百七十七字、七百零七秒。再断开一端并覆盖同一月文件，重连得到九百九十九字、九百零九秒。全量同步后两个进程重启，文件内容逐字节相同，完整统计与历史归档一致。自动重连先送达统计所需的版本，部分固定路径的最新快照需要一次全量同步才对齐。
- `node tests/hostStatisticsMonthlyAcceptance.mjs` 在端口九二五一与九二五二模拟乱序和重复到达。传入 `--fast-note-sync` 使用端口九二五三与九二五四的空白隔离库，并要求同步服务监听在本机回环端口一九二七零。两个模式都重启实际 Obsidian 进程。

## 原独立版本方案的范围与决定

- 默认目录为 `Template/数据/学习统计`；插件目录只保留设置与主题，不再保存运行中的统计快照。
- 每次插件运行生成随机统计记录编号，没有固定设备编号。记录只保存本次运行产生的统计，版本递增并使用独立版本文件，当前运行保留最近两个已验证版本；相同编号只取最新版本，不把整个汇总结果写回为新增量。
- 各端读取全部有效记录，字数、同篇笔记明细、小时秒数相加；不扣除多端时间重叠。保留时区偏移、采集覆盖与规则历史。
- 历史统计作为唯一初始记录迁入，迁入前保存完整备份。初始记录已存在时核验内容，不能把复制的旧历史再加一次。
- 清空、导入、恢复发布带父操作编号的替换记录；旧世代统计保留但不再计入。乱序到达等待前置操作，并发替换报冲突，不能任意选一个覆盖。
- 路径重命名发布针对已有记录的映射，不改其他运行的统计文件。
- 损坏、同版本异内容、记录删除保留上次有效结果并提示，不自动以零覆盖。普通统计变更通过现有局部刷新通知图表。

## 测试接口与验收标准

1. 统计存储公开接口：两份独立记录相加；重复、旧版本、乱序不重复累计；损坏不丢旧值；重启不重计；清空、导入、恢复阻止旧数据复活。
2. 活动服务公开查询与导出：迁移前后字数、小时桶、明细、设置、主题和历史等价；本机输入口径及五分钟空闲阈值不变；远端统计更新不算本机输入。
3. 持久化接口：持续字数及时长采集只写普通目录；设置不变时 `saveData` 零调用；同步读入不回写统计或设置。
4. 隔离 Obsidian：重复接收普通 JSON 时图表汇总正确、插件实例不变、无卸载／重载、原节点保留；既有图表与编辑设置验收通过。
5. CMBK：先备份插件完整目录及真实统计；安装后逐项核对历史与配置，观察普通目录写入和实例稳定性；不填造正式统计，不改图表配置及无关插件。

真实手机、跨网络同步延迟不由桌面模拟证明；交付中明确区分。
