# 贡献图功能完善规划与计时反馈方案

更新日期：2026年11月15日。

状态：待用户审查。当前基线为已安装到 CMBK 的零点二十点一。本次仅整理规划与方案，不包含功能实现，也不代表已批准后续开发或安装。

近期优先改善计时状态的可解释性，再利用已有统计增加学科周回顾、单篇笔记历史和复盘导出。第一项的详细方案见第二部分；后续功能保留为待逐项确认的规划。

## 一 功能完善规划

### 已有能力

当前已有每日热力图、单日小时柱状图、一周节奏、日期日历、文件夹筛选、每日目标、笔记明细及点击打开、键盘操作、图表局部刷新、自动保存、备份与恢复、普通目录统计同步和多端汇总。后续开发应复用这些能力。

空闲阈值默认五分钟：达到阈值后暂停，并撤回最后一次正文操作后的整段空闲尾段；未满阈值恢复正文操作则保留间隔。未满阈值就切到后台、打开弹窗、切换笔记或正常退出，仍按原规则结算至中断。改变这些边界属于统计口径变更，需要单独审查。

### 功能顺序与边界

| 顺序 | 功能 | 建议的最小范围 | 价值与成本 | 数据边界 |
| --- | --- | --- | --- | --- |
| 一 | 计时反馈与临时暂停 | 暂停原因、状态栏操作、暂计说明、空闲回撤反馈 | 便于核对计时，成本中等 | 主要增加运行状态，不新增统计格式 |
| 二 | 按学科的周回顾 | 每日趋势、学科分布、投入最多的笔记、达标情况、上周同期对比 | 帮助安排学习投入，成本中等 | 复用日期、小时和笔记累计 |
| 三 | 单篇笔记历史 | 七天、三十天、全部历史的时长、日期分布及日级字数 | 适合反复阅读长笔记，成本低到中等 | 有记录的天数不能当作复习次数 |
| 四 | 复盘导出 | 当前范围的 Markdown 报告与 CSV 明细 | 便于留存和外部分析，成本低到中等 | 日级字数与小时级时长分别组织，避免重复计算 |
| 五 | 明细搜索与排序 | 按名称和路径搜索，按时长或名称排序 | 减少查找操作，成本较低 | 保留现有打开笔记及文件缺失提示 |
| 六 | 周视图定位小时 | 宽窗点击具体小时后进入对应明细，窄窗保留整天入口 | 减少操作，成本中等 | 复用已有小时详情及焦点恢复 |
| 七 | 精确时长提示 | 主图保持分钟展示，悬浮或详情显示分秒 | 便于核对累计，成本较低 | 不改变原始秒数和汇总方式 |
| 八 | 导入预览 | 展示日期范围、总量、是否含时长及替换影响 | 降低误导入风险，成本中等 | 导入仍是整份替换，执行前自动备份 |
| 九 | 数据状态摘要 | 上次保存时间、有效记录数量、最近读入记录时间及错误 | 便于诊断，成本低到中等 | 本机文件信息不能证明其他端已全部同步 |
| 十 | 误扣恢复与手工修正 | 先评估恢复最近一次误扣，再考虑按笔记补记和扣减 | 解决误判，成本中到高 | 需要来源、撤销和同步去重，不能直接覆盖共享汇总 |
| 十一 | 精确会话与跨端重叠处理 | 先明确会话定义、时间重叠的归属，再新增区间采集 | 成本较高，后置 | 现有小时累计不能还原精确起止或完成重叠去重 |

上述条目均为规划，不随第一项一并实现。

### 学习分析的计算约定

周回顾比较本周与上周相同进度；完整周也可比较前一个完整周，界面须显示比较区间。学科按选定的文件夹层级聚合，同一笔记只归入一个分组，避免父子目录重复计数。

未采集日期、部分采集日期和已采集但无活动的日期分别展示。日均须说明分母；不把未采集日期直接补成零。部分采集日达到目标仍可标为已达标，低于目标时保留采集不完整提示。

时间与增删字数可以并列展示，但不推导学习效率或掌握程度。当前没有分别采集阅读和编辑时长，不能由字数倒推出两者比例。单篇笔记的最近活动只能按现有数据给出有记录的日期，不能伪造精确会话时间。

## 二 计时反馈与临时暂停方案

### 目标与本次范围

用户应能随时知道是否正在计时、为什么暂停、累计中是否包含本机暂计尾段，以及是否刚刚发生空闲回撤；需要休息或整理资料时，可以直接暂停本次时长采集。

本项包含五项可独立验收的能力：明确的状态与原因、可操作的状态栏、暂计与阈值说明、一次性的回撤反馈、临时暂停与恢复命令。设置页同步展示同一状态。

本项不增加周报、补记、误扣恢复、会话时间轴、跨端去重、自动恢复倒计时或新的统计设置。不调整五分钟默认阈值、十五秒结算心跳、自动保存间隔和现有空闲扣除规则。

### 建议先审查的三个决定

| 决定 | 推荐方案 | 后果 |
| --- | --- | --- |
| 临时暂停的有效期 | 仅当前插件运行；不跨设备、不写入设置，插件重载或应用重开后清除 | 实现简单；发生重载后会按全局开关重新采集，状态栏必须准确展示结果 |
| 提前中断时如何结算 | 保留现有规则，未满阈值的尾段正常保留；已到阈值则先回撤 | 本项只增加解释与控制，不同时改变统计口径 |
| 反馈与刷新频率 | 状态随事件和原十五秒心跳更新；悬浮或聚焦时读取最新快照；不新增逐秒计时器，不主动弹空闲提示框 | 减少打扰；剩余时间标为约数，不能承诺整秒跳变或阈值瞬间刷新 |

以上是推荐取舍，待审查后固定。若要求临时暂停跨重载保留，应先补充本机状态的持久化设计，不能把它直接作为可同步的全局设置。

### 状态与显示优先级

状态由当前事实计算，不按最后收到的某个事件盲目覆盖。时间结算始终由计时核心负责，界面状态不能反过来伪造活动。

| 优先级 | 条件 | 状态栏建议文案 | 继续计时的条件 |
| --- | --- | --- | --- |
| 一 | 全局时长统计关闭 | 时长：未启用 | 用户在设置中开启 |
| 二 | 当前运行已手动暂停 | 时长：手动暂停 | 用户明确恢复，且当前环境允许计时 |
| 三 | 没有可用的前台聚焦窗口 | 时长：后台暂停 | 有可用窗口重新聚焦后重新检查上下文 |
| 四 | 当前窗口存在阻塞弹窗 | 时长：弹窗暂停 | 弹窗关闭后重新检查上下文 |
| 五 | 当前不是可采集的 Markdown 视图 | 时长：当前页面不计时 | 切回有效笔记 |
| 六 | 笔记不在全局采集范围 | 时长：范围外 | 切回范围内笔记或修改范围 |
| 七 | 用户操作位于正文外，当前会话已结束 | 时长：等待正文操作 | 回到正文产生有效活动，或发生既有的合法恢复事件 |
| 八 | 计时核心因休眠迹象或时钟异常中断 | 时长：计时已中断 | 新的有效正文活动重新开始，不补计中断 |
| 九 | 计时核心已因空闲到期暂停 | 时长：空闲暂停 | 新的有效正文活动重新开始，不补计空闲 |
| 十 | 其余有效活跃状态 | 时长：计时中 | 按原心跳结算 |

同时满足多个条件时显示最高优先级；详细提示可补充其他阻塞条件。例如手动暂停时窗口也失焦，主状态仍为手动暂停；恢复后若仍有弹窗，显示弹窗暂停。

窗口是否聚焦应以当前有效窗口和正文上下文为准。主窗口与弹出窗口切换时，不能让旧窗口稍晚到达的失焦事件覆盖新窗口的有效状态；允许合并同一轮事件后重新读取上下文。同一路径在两个视图中打开时，还需按视图容器及所属文档识别，不能只比较路径。本项保留单一有效会话，不新增多窗口并行累计，也不直接禁用原有弹出窗口支持。

“计时已中断”与“空闲暂停”分开：短于空闲阈值的长心跳缺失也可能触发中断，不能编造为已经扣除五分钟。

### 状态栏与键盘操作

状态栏保持一行短文，不常驻显示完整路径、累计和倒计时。鼠标悬浮或键盘聚焦时显示详细快照，单击切换临时暂停／恢复。首版不新增菜单或独立统计面板。

计时中的详细快照示例：

```text
时长统计：计时中
当前笔记：临床医学／内科学／心律失常
今日累计：37 分钟，多端汇总，按当前全局采集范围
其中本机今日暂计：2 分 10 秒，已含在今日累计中
距离空闲阈值：约 3 分钟
单击暂停本次时长统计
```

手动暂停时，提示显示“仅暂停本次时长采集，字数统计仍按原开关运行”“单击恢复”；并说明临时暂停在插件重载或应用重开后结束。全局未启用时点击只作说明，不隐式修改全局开关。

状态栏控件可通过键盘进入，回车和空格执行同样的操作，有清晰焦点和动作名称。状态文字不应通过实时播报在每次心跳重复打断用户；只有手动操作及重要状态变化作适度反馈。

桌面窄窗口中只保留短状态。移动端即使不显示桌面状态栏，也须可通过命令面板和设置页使用暂停／恢复；移动端的具体呈现须在实施时核对宿主能力，不能由桌面模拟宣称完成实体手机验收。

### 暂计数据的含义与刷新

暂计指当前运行中，自最后一次有效正文活动后已经通过心跳计入、但仍可能因空闲到期撤回的尾段。尚未通过心跳计入的秒数不混进“已含在累计中”的暂计数字。

今日暂计只取该尾段落在今天本地日期内的部分，且仅在当前笔记属于提示所用范围时展示；跨午夜不能把昨天的尾段全部列为今天暂计。今日累计读取现有日统计，按当前全局采集范围筛选，与图表各自的筛选范围作清楚区分。

多端累计可能包含其他运行尚未确认的尾段，当前端无法判断它们的暂计状态，因此只标“本机今日暂计”，不把累计减去本机暂计后的数字称为全部已确认时长。

剩余时间根据单调时钟与最后有效活动时间计算，并向上取整为约数分钟；真实活动、上下文变化、手动控制和原十五秒心跳更新展示。悬浮或键盘聚焦时重新读取快照，不新增逐秒定时器。

阈值已经到达而核心尚未处理时，提示显示“已到空闲阈值，等待计时检查”，不自行扣减或提前宣布已完成回撤。正常运行由下一次原有心跳或有效结算入口处理；卡顿和休眠不承诺固定响应秒数。

读取或格式化快照必须是纯查询：不调用活动、结算、保存或时钟观察入口，不延长最后活动时间，不更新最后心跳时间。频繁悬浮、聚焦状态栏和刷新设置页均不能改变计时结果。

### 空闲回撤反馈

计时核心第一次将活跃会话变为空闲时，产生一次结构化的到期结果；不能根据状态文字变化或统计总量下降推断，因为远端同步和数据替换也可能改变总量。

到期结果至少包含笔记路径、空闲开始和本次检测时间、已经撤回的暂计秒数，以及本次直接丢弃而未曾计入的秒数。各字段来自同一次结算，避免界面另读时间后出现不一致。

界面区分两类文案：有实际已计时长被撤回时显示“已撤回本次空闲暂计”，并说明已撤回量及未计入余量；没有已计尾段时显示“空闲已暂停，该段未计入”，不声称扣除了并不存在的记录。

例如最后一次操作后，二百八十五秒已经计入，第五分钟触发检查，则实际撤回二百八十五秒，剩余十五秒直接不计入；整段五分钟最终均不保留。不能把总量实际下降二百八十五秒说成已经从存量中扣除三百秒。

首版仅在状态栏详细提示及设置状态区保留当前运行最近一次真实回撤的时间、路径和说明，不弹阻塞对话框，不写入持久化日志，不改变现有图表数据结构。重复心跳、重复暂停和刷新界面都不生成第二次记录。长心跳中断时若核心也实际撤回了已计尾段，照实记录撤回量，但状态原因仍按中断展示，不能伪装为一次正常心跳到期。

在后台发生回撤时，记录该结果供返回后查看，不另建通知队列。插件重载、清空、导入或恢复完成后清除这条运行期说明，避免它被误认为仍在描述新的统计。

### 临时暂停与恢复规则

临时暂停由活动服务维护一个本次运行的标志，所有时长入口检查同一标志。正文输入、滚轮、触摸、窗口恢复、笔记切换及弹窗关闭均不能绕过它；字数统计继续按现有设置工作。

暂停执行顺序为：先设置手动暂停保护，阻止回调重入时启动新会话，再由核心结算截至本次操作时刻并结束旧会话，关闭当前时长采集覆盖区间，通知状态与必要的覆盖变化，并强制保存一次。手动保护阻止新采集，但不阻止这次最终结算。若尚未到空闲阈值，尾段按原规则保留；若已到阈值，先执行既有回撤。关闭覆盖区间需标记脏状态，不能只改内存后漏保存。

重复暂停保持幂等，不新增覆盖区间，不重复结算，不反复强制写盘。保存失败时继续保持手动暂停，并展示现有保存失败状态；不能因为写盘失败重新开始计时。

恢复只清除手动暂停，不补计暂停期间。全局时长开启时，从恢复时刻重新开启覆盖区间；该区间表示采集功能可用，后台和空闲仍按原计时规则处理。若没有可用正文，则先显示相应阻塞原因，实际会话等合法上下文恢复后再开始。关闭的全局开关不被恢复命令隐式打开。

重复恢复不重启正在运行的会话，不重复开启覆盖，不重复保存。手动暂停期间修改文件夹范围、全局开关或导入统计，都不隐式清除暂停标志；重新开启全局开关后仍需显式恢复。导入、清空和恢复数据时不得因原有初始化路径自动打开新的时长覆盖区间。

后台保存、导出和正常退出仍可执行，但不能产生手动暂停期间的时长。临时暂停标志不写入设置、不向另一台设备传播；这次操作形成的已结算统计和采集覆盖仍正常保存与同步。另一台设备的正常采集不会被本机暂停中止。多端覆盖是汇总结果，因此本机暂停期间若其他设备仍在采集，汇总视图仍可能显示有覆盖。

插件重载或应用重开后，该临时标志清除，按全局设置重新初始化；若在此前暂停期间保存失败，仍适用原有异常退出风险。当前方案不承诺跨重载保留暂停。

### 自有控件和命令面板的特殊边界

新增状态栏控件属于插件自己的控制入口。观察器要在通用正文外点击判断前识别它：操作控件既不构成正文活动，也不能被通用捕获监听先执行一次意外暂停，从而改变结算时刻。控制入口只执行用户选定的动作，不通过模拟正文事件实现恢复。

命令面板仍按现有阻塞弹窗规则暂停。在面板里执行恢复时，只清除手动标志；面板尚未关闭时不能开始计时。面板关闭后重新获取当前视图、范围、窗口可见性和聚焦状态，再决定是否开始新的会话。

新增两条明确命令：“暂停本次时长统计”“恢复本次时长统计”。命令与状态栏复用同一操作入口；全局未启用时仅提示需先开启，不修改设置，也不清除已有临时暂停标志。恢复操作必须要求观察器重新核对当前上下文，不能因旧的笔记路径缓存相同而直接跳过恢复。

正常的正文外操作、原有日历和设置弹窗继续沿用现有规则，不把本项扩展成重新设计整个活动事件采集。

### 典型场景

| 场景 | 预期结果 |
| --- | --- |
| 已有十分钟有效活动，随后空闲满五分钟 | 保留前十分钟，整段空闲不保留，出现一条真实回撤说明 |
| 空闲四分钟后点击暂停 | 按原规则保留四分钟尾段，随后时长停止，字数仍按原开关采集 |
| 暂停后滚轮、输入、换笔记，再关闭弹窗 | 仍为手动暂停，没有新增时长 |
| 在命令面板执行恢复 | 面板关闭且上下文有效后开始新会话，不计面板停留及此前暂停时间 |
| 暂停时切到范围外，再恢复 | 手动标志解除，但仍显示范围外且不计时；回到范围内后按正常规则恢复 |
| 暂停期间跨午夜 | 不给新一天添加本机时长，恢复后的覆盖及会话从实际恢复时刻开始 |
| 最后活动在午夜前两分钟，今日累计提示被打开 | 今日暂计只显示今天已计入的部分，回撤仍覆盖整段跨日尾段 |
| 空闲后反复悬浮状态栏或刷新设置 | 不延长活动和心跳，不阻止回撤，不重复产生回撤说明 |
| 主窗口与弹出窗口切换焦点 | 按当前有效正文重新求值；手动暂停对本插件所有窗口有效 |
| 另一端同步来新的统计 | 原汇总正常更新，本机手动标志和当前回撤说明不被普通同步重置 |
| 手动暂停后重载插件 | 临时标志清除，按全局开关重新初始化，状态文字准确反映新状态 |

### 实现职责与接线

沿用现有服务、观察器和计时核心，不引入第三方依赖，不另建通用状态机框架。以下接口名称为拟议名称，实施时可按既有风格调整，但职责和调用链必须保留。

| 位置 | 拟议改动 | 真实调用方或消费方 |
| --- | --- | --- |
| `src/time/types.ts` | 定义只读状态快照、上下文原因及一次性回撤结果 | 核心、服务、观察器和展示使用同一契约 |
| `src/time/timeTracker.ts` | 提供纯查询快照；在真实到期转移中产生一次结果；区分到期与时钟中断 | 服务读取快照并接收结果；原区间加减仍走原入口 |
| `src/activity/EditActivityService.ts` | 维护临时标志和上下文；统一暂停／恢复、覆盖区间及保存；提供 `getTimeTrackingSnapshot` | 状态栏、设置页及命令共同使用，所有采集入口执行同一保护 |
| `src/time/TimeActivityObserver.ts` | 识别上下文原因、自有入口，操作后强制重新核对；维护状态栏与生命周期 | 原窗口／正文事件、主入口控制命令及服务状态变化 |
| `src/time/timeTrackingPresentation.ts` | 拟新增小型纯函数模块，集中生成短文案、详细提示及约数 | 状态栏与设置页复用；不负责计时或持久化 |
| `src/activity/EditActivitySettingTab.ts` | 时长分组接入共享状态及暂停／恢复按钮 | 服务状态通知更新，关闭设置时释放订阅 |
| `src/main.ts` | 注册两条命令并连接服务操作与观察器上下文重检 | Obsidian 命令面板，卸载沿用原清理入口 |
| 服务中的 `EditActivityChangeEvent` 及 `src/processor/graphChanges.ts`、`graphRefreshScheduler.ts` | 增加仅运行状态变化的通知类别，图表忽略这种通知 | 状态栏／设置监听，图表不因此查询或重绘 |
| 对应测试与独立宿主脚本 | 覆盖纯计算、服务、观察器、设置与真实命令交互 | 下述逐项验收表及既有全量回归 |

观察器只提供上下文事实并识别真实活动，服务统一决定手动开关与展示状态，核心仍唯一决定区间结算。手动控制后的上下文重检通过主入口或观察器的明确方法接线，服务不直接读取宿主 DOM。

手动暂停会真实改变时长采集覆盖，须使用现有统计变化通知刷新相关图表。纯文案、暂计快照及回撤说明更新使用独立状态通知，不借用统计变化事件，不触发图表全量查询。

首版不扩展公开的 `window.contributionGraphApi`，也不改变导入导出统计格式。所有打开覆盖区间的既有路径都要检查临时标志，包括启用、范围修改、数据替换与恢复；不能只在普通正文活动入口加一次判断。

### 实施顺序

| 阶段 | 交付范围 | 验证方式 |
| --- | --- | --- |
| 一 | 固定三项待审查决定及状态表，先写核心和服务失败测试 | 旧实现应无法满足纯快照、原因和手动保护行为 |
| 二 | 核心快照、到期结果、服务临时标志、覆盖和保存 | 核心与服务行为测试通过，旧计时口径回归通过 |
| 三 | 状态栏、共享文案、设置按钮及两个命令 | 观察器和设置测试先失败再通过；纯状态变化不触发图表查询 |
| 四 | 独立宿主的真实点击、命令面板、弹窗、焦点和重载 | 注入时钟与真实事件分别验证，不以直接调用私有方法代替交互 |
| 五 | 全量检查及审查差异；按届时授权决定是否安装 | 全量测试、类型检查、构建、打包，核对所有需求接线 |

审查通过后可分阶段实施，但最终交付须覆盖本项全部五项能力，不以只改状态文案代替临时暂停或暂计说明。

### 验收标准

以下是实现前固定的通过条件。测试从用户行为和公开服务结果推导，不按内部字段布局编写镜像断言。

| 编号 | 验收要求 | 主要验证层 |
| --- | --- | --- |
| 一 | 活跃、手动暂停、后台、弹窗、非正文、范围外、空闲和时钟中断分别有准确状态；组合条件遵守优先级 | 服务、观察器 |
| 二 | 在相同活动序列中反复读快照与完全不读快照，最终区间和总秒数相同 | 核心 |
| 三 | 暂计仅含已经计入的本机尾段；跨午夜拆分正确；全局范围与多端汇总文案清楚 | 核心、服务、展示 |
| 四 | 五分钟到期正常回撤，只生成一条结果；重复检查、暂停和渲染不重复反馈 | 核心、服务 |
| 五 | 实际撤回二百八十五秒并丢弃十五秒时，反馈区分两者；没有已计尾段时不虚报扣除 | 核心、展示 |
| 六 | 手动暂停前按旧规则结算；暂停后输入、滚动、焦点变化、切笔记及弹窗关闭均不计时 | 服务、观察器、宿主 |
| 七 | 手动暂停只影响时长，真实字数采集仍按原策略工作 | 服务、宿主 |
| 八 | 暂停关闭本机覆盖并保存一次；重复操作幂等；保存失败后仍保持暂停和待重试数据 | 服务、存储 |
| 九 | 恢复不开启已关闭的全局开关，不补计暂停时间，覆盖从恢复时刻开始 | 服务 |
| 十 | 修改范围、关闭再开启全局开关、导入、清空和恢复统计，不绕过当前手动暂停；普通同步也不重置它 | 服务、存储 |
| 十一 | 真实点击状态栏及回车／空格不会被正文外捕获监听抢先结算，也不会刷新正文活跃时间 | 观察器、宿主 |
| 十二 | 命令面板内恢复不计面板停留；关闭面板后即使笔记路径未变，也能正确重检并开始 | 观察器、宿主 |
| 十三 | 主窗口与弹出窗口交替聚焦，旧窗口事件不覆盖新上下文；手动暂停跨窗口一致 | 观察器、宿主 |
| 十四 | 纯状态通知不触发统计查询或图表重建；真实覆盖变化仍刷新图表 | 刷新调度测试、宿主 |
| 十五 | 暂计及回撤说明不新增日常设置写入，不改变现有保存节奏，且说明不进入导出 | 服务、存储 |
| 十六 | 插件重载后临时标志清除、旧回撤说明消失，状态栏和命令无重复监听；旧历史、设置及主题保持一致 | 生命周期、宿主 |
| 十七 | 深浅色及窄窗口可读，键盘焦点可见，提示不遮挡关键操作；移动入口单独标明实际验收范围 | 展示、宿主 |
| 十八 | 原空闲扣除、跨小时／午夜、休眠保护、自动保存、退出保存及同步去重的既有测试继续通过 | 全量回归 |

除自动化验收外，桌面宿主至少执行一次真实五分钟空闲，用来核对状态、回撤解释和实际显示；注入时钟用于边界加速，两者不能相互替代。正式库不注入样例或伪造学习时间。

### 风险与取舍

| 风险 | 本方案的处理 |
| --- | --- |
| 静止阅读被判为空闲 | 保留已确认的自动扣除规则，说明原因；误扣恢复留在后续规划 |
| 插件意外重载解除临时暂停 | 明确本次运行有效的推荐语义；若要求保持暂停，审查时调整持久化方案 |
| 统计已有远端暂计，用户误以为其余全部确认 | 仅说明本机暂计，不展示无法证明的全局已确认量 |
| 显示刷新意外充当心跳或活动 | 快照为纯查询，使用对照行为测试阻止此回归 |
| 同一暂停被主入口和观察器重复处理 | 操作幂等、原因按当前事实计算，窗口切换后重新核对 |
| 手动暂停覆盖被其他初始化入口重新打开 | 核查所有覆盖开启点，覆盖设置修改及数据替换测试 |
| 新提示导致频繁图表刷新或配置同步重载 | 状态通知独立于统计变化，无新同步设置或持久化日志 |
